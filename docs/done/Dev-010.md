# Dev-010: Models tab, per-role LLM selection inside the app

[Feature] [Client] [Server] [Migration]

Changing a role's model meant editing `.env` and restarting the server, and a game with a key but no
`NARRATOR_MODEL` ran offline with no hint in the app. The player can now pick the model and the
reasoning flag of each of the seven roles from a new **Models** tab, and the choice applies to the next
call.

## 1. Findings

- `roleConfig` in `src/server.ts` read `.env` once at start and `LlmClient` held that table forever.
- The engine keeps one `EngineServices` object, and every role reads `llm.role(...)` per call, so a
  config swap needs no rebuilt services unless the game goes from offline to LLM.
- `clearSave` empties `settings`, so a model choice cannot live there: it would vanish on every new game.

## 2. Decisions

- Choices live in a new `role_config` table (migration 8) that `clearSave` leaves alone.
- Precedence per role: Models tab, then `<ROLE>_MODEL`, then the narrator's model; reasoning: tab, then
  `<ROLE>_REASONING`, then the role default. `src/models.ts` holds this as a pure function.
- The server edits the same `EngineServices` object in place and calls `LlmClient.configure`, so the
  tab can also switch the LLM on or off without a restart. A save is refused while a turn runs.
- The API key and the idle timeouts stay `.env`-only; the key never reaches the client.
- The OpenRouter model list is fetched by the server (no key), cached for an hour and only feeds the
  autocomplete and price hint; any well-formed `vendor/name` id is accepted when it is unreachable.

## TL;DR

A Models tab edits every role's model and reasoning flag at runtime, persists them in `role_config`
across new games and restarts, and applies them to the next LLM call without restarting the server.
