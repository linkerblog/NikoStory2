# Dev-013: An editable worldbuilding and a World tab

[Feature] [Engine] [DB] [Data] [Client] [Narrator]

The worldbuilding was a fixed `data/world.json` of three facts and a style line, read once at start-up and
sent to four roles. This makes it the author's own document: the template the author writes for the game
([Init], [Personality], [Initial history], [Tags], [WorldBuilding], [Biology], [Format]), editable in a new
World tab, validated by the engine, read fresh on every call, and delivered to each role according to what
that role could know.

## 1. Findings

- `WorldFacts` reached the narrator, the continuity check, the architect, the cast writer and the
  government writer. The interpreter, the NPC decider and the memory writer never saw it.
- Niko's personality lived in `data/niko.json` and reached the prompts through his sheet, so the author's
  [Personality] had nowhere to go.
- The Models tab already had the right shape for an install preference: a table the save wipe leaves alone,
  an endpoint to read and one to write, and a tab that never simulates.
- The author's [Init] and [Initial history] are Niko's own origin. Handing them to the NPC decider or the
  government writer would let the people of the world know where Niko comes from.

## 2. Decisions

- **One document, one gate.** `src/worlddoc.ts` holds the `WorldDoc` type, `parseWorldDoc` (the only
  validator, for the file and the tab), `compileWorld` and `publicWorld`. Bounds are in `WORLD_LIMITS`.
- **Install preference.** `world_doc` (migration 10) holds the author's edit in a single row. `clearSave`
  does not touch it, so Start new game keeps the world; "restore" deletes the row and the file's default
  returns. A damaged row reads as no edit.
- **Read fresh.** The engine reads the document on every call (`worldFacts`), so an edit applies to the next
  prompt with no restart, like the government.
- **Full or open.** The narrator and the continuity check get everything. The interpreter, the NPC decider,
  the architect, the cast writer and the government writer get `publicWorld`, which leaves out `premise` and
  `protagonist`. `WORLD_USERS` lists every role, and a test fails if a role is missing from it.
- **Niko's personality comes from the document.** `nikoSheet` overlays [Personality] on the sheet; an empty
  one keeps the data file's. The `personality` key left `data/niko.json`.
- **Prompts.** The narrator is told to follow `world.style`, to use `world.premise` for the fall and the
  landing without retelling it, and to treat `world.protagonist` as background that never grants an ability
  the events do not show. The interpreter and the NPC decider are told the world they receive is true.
- **The tab** shows the source (edited or default), one field per heading with a character or line count and
  an unsaved mark, the list of who reads the world and how much, and the compiled JSON the narrator receives.
  Restore needs two clicks. F4 toggles it.

## 3. What must not break

- The client never simulates: the tab edits text and calls the API.
- The engine is the only validator: a rejected edit changes nothing.
- Migrations are append-only; `clearSave` keeps `role_config` and `world_doc`.
- Every existing suite keeps passing; only the migration lists gained a `10`.

## 6. Out of scope

- Enforcing "Never talks" or a `>` greentext prefix in code: both are text the narrator receives.
- Letting the memory writer read the world, and versioning or history of edits.
- Any sexual action: the template's biology is background fact only, and the repository rule on consent
  still governs when one is added.
