# Dev-005 — Terminal-Tech UI Redesign

> Goal: a text-first interface that feels like a modern tech terminal, is fast to navigate
> with keyboard and mouse, and is easy on the eyes during long sessions.

## 1. Scope and non-goals

**In scope**
- Visual redesign of the whole client UI: layout, typography, color, motion, navigation.
- Keyboard-first navigation with full mouse support.
- A design-token layer so every color, size and spacing value lives in one place.

**Out of scope**
- Any change to simulation, memory or persistence logic.
- New gameplay features. The UI only renders state and sends commands.

**Rule that must not break:** the client never simulates. The UI draws snapshots and sends
commands; no game state lives in UI components.

## 2. Design principles

1. **Text is the interface.** No decorative chrome. Borders, glyphs and color carry structure.
2. **One glance, one answer.** The player must see where Niko is, what just happened and what
   they can do next without scrolling or opening menus.
3. **Keyboard first, mouse friendly.** Every action has a key; every key-action is also clickable.
4. **Calm by default.** Low-contrast chrome, high-contrast content. Color is meaning, not paint.
5. **Predictable.** Same panel, same place, every screen. No layout jumps between turns.

## 3. Visual language

### 3.1 Palette (dark, low-glare)

| Token | Hex | Use |
|---|---|---|
| `--bg` | `#0b0e14` | App background |
| `--bg-panel` | `#10141c` | Panel background |
| `--bg-raised` | `#171c27` | Hover, selected row, input |
| `--border` | `#252c3a` | Panel borders, dividers |
| `--fg` | `#c9d1d9` | Main text |
| `--fg-dim` | `#7d8590` | Secondary text, hints, timestamps |
| `--accent` | `#5ee6c4` | Focus, prompt, active tab, Niko |
| `--accent-2` | `#7aa2ff` | Links, zone names, selectable options |
| `--warn` | `#f2cc60` | Warnings, low resources |
| `--danger` | `#ff6b6b` | Damage, combat, errors |
| `--ok` | `#8ddb8c` | Success, healing, confirmations |
| `--mana` | `#b48ead` | Ether / mana readouts |

Rules:
- Text on background must meet at least **WCAG AA (4.5:1)**; `--fg-dim` is for non-essential text only.
- Never use color alone to convey meaning: pair it with a glyph (`✓`, `!`, `×`, `▲`).
- Ship a second theme later (amber phosphor, light) by swapping tokens only.

### 3.2 Typography

- Monospace only. Stack: `"JetBrains Mono", "Fira Code", "Cascadia Code", ui-monospace, monospace`.
- Base size `15px`, line height `1.6`. Narrative text max width `72ch` for comfortable reading.
- Ligatures **off** in narrative text, **on** in UI labels if the font supports it.
- Weights: 400 body, 600 headings and labels. No italics except for inner thoughts.

### 3.3 Glyphs and borders

- Panel borders: 1px solid `--border`, corner radius `4px`. No shadows, no gradients.
- Section headers use a bracket style: `[ STATUS ]`, `[ LOG ]`, `[ ACTIONS ]`.
- Bullets and markers: `▸` selected, `·` idle, `✓` done, `!` warning, `×` blocked.
- Keep glyphs inside standard Unicode blocks so they render in any monospace font.

### 3.3.1 Spacing scale

`4 / 8 / 12 / 16 / 24 px` only. Panel padding `12px`, gap between panels `8px`.

## 4. Layout

Three fixed regions plus a command line. Widths are fractions so it scales cleanly.

```
┌─ NikoStory2 ─────────────────────────────── T:0142  Day 3  14:20 ─┐
│ [ MAP ]                  │ [ LOG ]                   │ [ STATUS ]  │
│                          │                           │ Niko        │
│  ▒▒▒▒▒▒▒▒▒▒▒▒▒▒          │ > You step inside.        │ HP  ████░░  │
│  ▒ . . . . . ▒          │   Dust. Cold air.         │ Mana ███░░░ │
│  ▒ . @ . . D ▒          │   A door on the left.     │ Zone: Safe- │
│  ▒▒▒▒▒▒▒▒▒▒▒▒▒▒          │                           │ house, 10x15│
│                          │                           │             │
│ Legend: @ you  D door    │                           │ [ NEARBY ]  │
│                          │                           │ ▸ Door      │
├──────────────────────────┴───────────────────────────┤ ▸ Crate     │
│ [ ACTIONS ]                                          │             │
│  1 ▸ Open the door     2 ▸ Search the crate     3 ▸ Wait          │
├───────────────────────────────────────────────────────────────────┤
│ niko@world:~$ _                                      F1 help      │
└───────────────────────────────────────────────────────────────────┘
```

| Region | Width | Content |
|---|---|---|
| Map | 30% | Grid of the current zone, `@` for Niko, legend below |
| Log | 40% | Narrative feed, newest at the bottom, auto-scroll with pin |
| Sidebar | 30% | Status, nearby entities, inventory tab |
| Actions bar | full | The 3 turn options, always visible |
| Command line | full | Free input, history, autocomplete |

Responsive behavior:
- `>= 1100px`: three columns as above.
- `700–1099px`: Map collapses into a tab next to Status.
- `< 700px`: single column with a bottom tab bar (Log · Map · Status · Actions).

## 5. Navigation

### 5.1 Keyboard map

| Key | Action |
|---|---|
| `1` `2` `3` | Choose the matching turn option |
| `Enter` | Confirm selected option / send command |
| `↑` `↓` | Move selection; in command line, browse history |
| `←` `→` `↑` `↓` (map focus) | Move Niko one tile |
| `Tab` / `Shift+Tab` | Cycle focus between panels |
| `g` then `m/l/s/i` | Jump to Map / Log / Status / Inventory |
| `/` | Focus the command line |
| `Ctrl+K` | Command palette (search any action, setting or entity) |
| `F1` or `?` | Help overlay with every shortcut |
| `Esc` | Close overlay, clear focus, cancel |

### 5.2 Command palette

- Fuzzy search over actions, entities in the zone, settings and docs.
- Shows the key for each result so players learn shortcuts passively.
- Results grouped: **Actions**, **Nearby**, **Settings**, **Help**.

### 5.3 Focus and feedback

- The focused panel gets an `--accent` border. Only one panel is focused at a time.
- Selected option: `--bg-raised` background plus a `▸` marker.
- Every command gets feedback within 100 ms: a line in the log, a status flash or an error message.
- Errors are plain sentences with the fix: `Cannot open door: it is locked. Try: search crate.`

## 6. Components

| Component | Behavior |
|---|---|
| **Panel** | Titled box, scrolls independently, collapsible with `Enter` on the header |
| **Log line** | Timestamp (dim), actor tag, text. Niko lines use `--accent`, world events `--fg`, system lines `--fg-dim` |
| **Bar** | Text bar `████░░` with numeric value on hover or focus |
| **Option button** | Number + label, hover and focus states, disabled state with reason |
| **Tabs** | Underline active tab in `--accent`, number shortcut shown in the label |
| **Toast** | Bottom-right, 3 s, only for saves, errors and level-ups |
| **Modal** | Centered, dims background, traps focus, closes with `Esc` |
| **Tooltip** | On hover after 400 ms, also shown in the help overlay |

## 7. Motion

- Text reveal: typewriter at about 120 chars/s for new narrative, **skip with any key**.
- Panel focus and hover transitions: 120 ms ease-out.
- Cursor: block cursor, 1 s blink, stops blinking while typing.
- Honor `prefers-reduced-motion`: disable typewriter and blinking, render instantly.
- No screen shake, no flashing. Damage is a single red line flash under 200 ms.

## 8. Readability and accessibility

- Full keyboard operability, visible focus on every interactive element.
- ARIA roles: `log` for the feed (polite live region), `tablist` for tabs, `dialog` for modals.
- Text scale setting: 90% / 100% / 115% / 130%.
- High-contrast theme toggle and a "no color-only meaning" audit before release.
- Font choice and line width are settings, not hardcoded.

## 9. Implementation plan

Stack assumption: TypeScript client in the browser. Adapt names if the stack changes.

1. **Tokens.** Create `ui/tokens.css` with every value from section 3 as CSS variables.
2. **Shell.** Build the layout grid and empty panels with the responsive rules from section 4.
3. **Components.** Panel, Bar, Option, Tabs, Toast, Modal, Tooltip, each in isolation.
4. **Input layer.** One keymap module, one focus manager, one command palette.
5. **Data binding.** Panels subscribe to snapshots from the engine; no local game state.
6. **Motion and polish.** Typewriter, transitions, reduced-motion path.
7. **Accessibility pass.** Contrast check, screen reader check, keyboard-only run-through.
8. **Theme pass.** Verify a second theme works by swapping tokens only.

Suggested file layout:

```
client/ui/
  tokens.css
  layout.css
  components/
  input/keymap.ts
  input/focus.ts
  input/palette.ts
  panels/{map,log,status,actions,command}.ts
```

## 10. Acceptance criteria

- [ ] All colors, sizes and spacing come from tokens; no hardcoded values in components.
- [ ] A new player can complete a turn using only the keyboard, with no help screen.
- [ ] Every shortcut is listed in the help overlay and the command palette.
- [ ] Layout never shifts between turns; the Actions bar is always visible.
- [ ] Text contrast meets WCAG AA in the default theme.
- [ ] `prefers-reduced-motion` disables all animation.
- [ ] Works at 1280×720, 1920×1080 and a 390px-wide mobile viewport.
- [ ] No game state stored in UI components; everything renders from snapshots.
- [ ] `npm run check` passes.
