# Dev-014: Characters with memory and depth, and a world with daily life

[Feature] [Engine] [Data] [World] [Client]

The people of the world read as thin: a one-line personality, a one-line voice, one goal, and a prompt that
knows only the last five raw events and six generic world facts. This gives them three things the engine
can supply with no new state machine: what they remember, who they are (a few traits, a quirk, a fear and a
short past) and a world that says how an ordinary day goes. Needs, relationships and chained agendas are
left for later DEVs.

## 1. Findings

- `NpcContext` carries `recentEvents`, the last five raw events (`t3: Marta move N`). The ranked recall
  the narrator already uses (`recalledLines`, `src/memory.ts`) never reaches the `npc` role, although
  `memories` rows exist for every witness, NPCs included.
- A character is `personality` plus `voice` (`data/cast.json` temperaments, `data/npcs.json`). The `cast`
  role rewrites only those two. Two characters with different temperaments differ in tone, not in what they
  fear, notice or do out of habit.
- The world the NPC role gets is `facts` and `tags`. Nothing says what people eat, how the street sounds
  or what is normal, so a model fills the gap with generic fiction.
- `publicWorld` already separates what everyone knows from Niko's own origin; a new public section needs
  no new gate.

## 2. Decisions

- **Recall for NPCs, same ranking.** `Engine.npcContext` calls `recalledLines` for the actor, with the
  characters it can see and the words of its own goal as the query. `memories` joins `recentEvents` in the
  payload; the engine reads, the model only reads. Offline play is unchanged because the offline decider
  never calls the prompt.
- **Depth is four small fields, all or nothing.** `traits` (2 to 4 words), `quirk`, `fear` and `backstory`,
  stored flat in `entities.data` next to `personality` and `voice`. One validator, `parseDepth` in
  `src/cast.ts`, serves the pool, the cast role and the authored NPCs. A depth that fails it is dropped
  whole, never trimmed.
- **The pool gives depth offline.** Every temperament in `data/cast.json` carries a `depth`, so a new game
  with no network already has characters with a quirk and a past. The `cast` role may write its own;
  when it writes a personality without a valid depth, the pool depth is removed, because a "stern" character
  keeping a "scatterbrained" quirk is worse than none.
- **The past is private and neutral.** Backstory text has no pronouns, names, numbers or mention of Niko or
  the fall; it only has what a person of this world could have lived. The prompt tells the model it colors
  choices and is never recited.
- **Daily life is a new public section.** `WorldDoc.daily_life` ([Daily life], one line per entry) compiles
  to `WorldFacts.life` and is kept by `publicWorld`, so the narrator, the NPC decider, the cast writer and
  the other open roles all get it. A saved `world_doc` without it still validates (`?? []`). It is texture,
  never plot: the prompts say so.
- **Not a new fact list.** `life` stays apart from `facts` so the continuity check keeps treating `facts` as
  hard contradictions and `compileWorld(...).facts` keeps its shape.
- **Placeholders for the author.** The default `daily_life` lines in `data/world.json` are neutral
  scaffolding written to fit the existing tags; the author can replace them in the World tab.

## 3. Changes

### 3.1 Memory in the NPC prompt

- `src/npc.ts`: `NpcContext.memories: string[]`; `payload` sends it; the prompt explains that memories are
  what the character remembers, that they must not be contradicted or invented, and that `world.life` is
  for small details only.
- `src/engine.ts` `npcContext`: build the recall query from the actor and fill `memories`.

### 3.2 Character depth

- `src/cast.ts`: `Depth`, `DEPTH_LIMITS`, `parseDepth`, `readDepth(data)`; `Temperament.depth`; `loadCast`
  rejects a malformed depth; `generateCast` copies it into the NPC data; `Personality.depth`;
  `castPrompt` and `parseCastDraft` ask for and validate it.
- `src/world.ts` `applyPersonalities`: writes the cast role's depth, or removes the pool depth.
- `src/npc.ts`: `NpcActor` carries the depth and the prompt renders it.
- `data/cast.json`, `data/npcs.json`: depth for the ten temperaments and for the two authored characters.

### 3.3 Daily life

- `src/worlddoc.ts`: `daily_life` in `WorldDoc`, `WORLD_LIMITS`, `parseWorldDoc`, `compileWorld`; the
  `WORLD_USERS` text of the roles that read it. `src/world.ts`: `WorldFacts.life`.
- `src/narrator.ts`: one rule, `world.life` is how ordinary days go: use it for texture, never as plot.
- `data/world.json`: `daily_life` lines. `public/index.html`: a [Daily life] field in the World tab.

## 4. What must not break

- The engine is the only writer of state; the model only proposes, and a depth or a recall never changes a
  tile, a roll or an outcome. No `Math.random`: depth is drawn in `generateCast` from the seeded stream, so
  the same seed replays the same people.
- The pool draw order is kept (names, then temperaments, then spawns), so existing seeds still place the
  same characters; depth rides on the temperament already drawn.
- A role that stands for someone else never receives `premise` or `protagonist`; `life` is public.
- Migrations stay append-only: no schema change. A saved game without depth reads as before.
- Every existing suite keeps passing.

## 7. Out of scope

- Needs that build with the tick, routines by hour and a time of day.
- Relationships and attitude toward Niko, and agendas that chain after the first reveal.
- NPC-to-NPC gossip, objects with a history and incidents other than the landing.
- Rewriting memories in the character's own voice with the `memory` role.
