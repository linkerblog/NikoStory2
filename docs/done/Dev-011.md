# Dev-011: Hit points, unarmed strikes and incapacitation

[Feature] [Engine] [Data] [Narrator] [Client]

Nobody can be hurt today: `data/rules.json` says Niko cannot attack or take damage. This adds health as
an engine rule. A character has hit points, the Ether Core absorbs damage before they do, a strike is
rolled by the engine from the seed, and a character at 0 HP is incapacitated for a few ticks instead of
dying. The interpreter only proposes an `attack` effect; the narrator sees health as words, never as
numbers.

## 1. Findings

- Ether already lives in `entities.data` (JSON) and only `src/engine.ts` writes it. HP fits the same blob,
  so the schema does not change.
- The generated cast (`src/cast.ts`) and the legacy saves have no `hp`. A default from the rules covers
  both without rewriting rows.
- `brace` only matters in the fall today (`fallStep`, `fall_brace`). The ability case in `applyAction`
  spends Ether and records a roll, nothing else.
- `sheet: { name, ...niko.data }` goes to the narrator and the interpreter verbatim, so a raw `hp` key
  would reach both prompts. The same rule already keeps distances out as numbers.
- An NPC acts only inside `stepWorld`, from a stale `ents` snapshot. Any new write to an NPC must read
  the row fresh.

## 2. Decisions

- **No migration.** There is no schema change: `hp`, `hp_max`, `guard_until` and `downed_until` are keys
  of `entities.data`. A missing `hp` reads as full health from `rules.combat` (Niko 20, an NPC 12), so an
  old save and a generated cast work untouched. This replaces the backfill migration first proposed.
- **Ether first.** A blow costs `etherPerHp` Ether per point it would remove, as long as the target has
  that Ether; the rest hits HP. A hard landing already empties Ether, so Niko arrives vulnerable.
- **`brace` is a guard.** An ability with `guard_ticks` sets `guard_until = tick + guard_ticks`; a blow
  that lands while guarded is multiplied by `guardFactor` and rounded down. The fall keeps its own path.
- **Strike.** `rngFor(seed, tick, "strike:<attacker>:<target>")`: the first draw decides the hit
  (`strike.hit`), the second the damage (`strike.min`..`strike.max`). Reach is adjacency, which already implies sight.
- **Incapacitation, not death.** At 0 HP the character is down until `downed_until = tick + downedTicks`,
  then stands with `recoverHp`. A downed NPC does not act, move or talk. A downed Niko cannot choose: his
  turn passes as a wait, the interpreter is not called, and the world keeps ticking.
- **Regeneration.** `regen.amount` HP every `regen.every` ticks, far slower than Ether.
- **Words, not numbers.** `bands` in the rules map the HP fraction to `unhurt`, `hurt`, `badly hurt`,
  `near collapse` and `down`. The narrator and the interpreter get the band; the sheet is stripped of the
  raw keys. The client is a display and may show numbers, like Ether.
- **NPCs may fight back, only when provoked.** The `npc` role may propose `attack` against a character
  that struck it (a `hit` or `miss` event it witnessed within `retaliateTicks`). Anything else is rejected
  with a reason. Offline there is no decider, so NPCs stay passive.

## 3. Changes

### 3.1 Rules and data

- `data/rules.json`: a `combat` block with every number above; `brace` gains `guard_ticks: 2`; the last
  `limits` line becomes "Niko has no weapons: he strikes with his fists, only at someone right next to him."
- `data/niko.json`: `hp` and `hp_max` (20).
- `src/rules.ts`: `GameRules.combat`, validated like the rest (a malformed block is rejected);
  `Ability.guard_ticks`.
- `src/combat.ts` (new, pure): `CombatRules`, `vitalsOf`, `healthBand`, `rollBlow`, `mitigate`,
  `publicData`.

### 3.2 Engine

- `Action` gains `{ type: "attack"; target: string }`; `parseFreeAction` maps attack, hit, punch, strike,
  kick and slap plus a name, so the offline interpreter works.
- `Effect` gains `{ kind: "attack"; target }` in `sanitizeEffect`, `describeEffect`, `actionToEffects`
  and both prompts.
- `Engine.strike(attacker, target)`: one function for Niko and NPCs. It re-reads the target, rolls, applies
  guard and Ether, writes the data, records `hit`/`miss`, then `down` when HP reaches 0, and closes any
  open conversation of the downed character without revealing its fact.
- `stepWorld`: recovery and regeneration run before the snapshot is read; downed NPCs are skipped.
- `runTurn`: a downed Niko passes the turn.
- `talk` and `reply` reject a downed NPC.
- Events `hit`, `miss`, `down` and `recover` carry witnesses like every other event; `src/memory.ts` has
  templates and importance for them, and the memory prompt forbids numbers for damage or health.

### 3.3 Narrator, state and client

- `Context`: `visible[].health` and a `health` word in the sheet; the narrator prompt forbids stating
  health, damage or Ether as numbers.
- `state()` and `debug()` report `hp`, `hp_max`, `health` and `down` for Niko and `health` for visible NPCs.
- `public/index.html`: an HP row beside Mana, a `down` tag, and the health word next to each NPC.

## 4. What must not break

- The engine is the only writer; the interpreter and the `npc` role only propose an `attack`.
- One action API: Niko's attack and an NPC's attack go through `strike`, the same tile and sight checks.
- Determinism: no `Math.random`; same seed and same actions give the same fight.
- Witnesses: only whoever could see a blow reacts to it or remembers it.
- No migration is edited; `MIGRATIONS` stays at 8 entries.
- The fall has no company: nothing here runs while `phase` is `fall`.

## 7. Out of scope

- Weapons, equipment, armor and ranged attacks.
- Fall damage: a hard landing still only empties Ether.
- Deterministic retaliation offline, and NPCs starting a fight on their own.
- Death, permadeath and healing items.
- NPCs reading `facts_known` about who hurt whom.
