# Dev-006: Free-text interpreter — no preset options, one model per role, quality passes

[Feature] [Architecture] [Engine] [Narrator] [Client] [Data] [DB]

The player already types free text, but the game still thinks in preset options: the engine builds a
closed action list, the narrator is told to offer three options, and anything the parser does not
recognize becomes a `say` event with no effect on the world. This DEV removes preset options and
makes an LLM role, the **interpreter**, read what the player wrote and propose typed effects under
the rules of the game. The engine validates and commits them, so it stays the only writer of state.
Speed is no longer a goal: every role gets its own model and reasoning flag, long calls are not cut
off, and two quality passes (a continuity check and LLM-written memories) run before a turn closes.

## 2. Findings / current state

Observations come from reading v0.4.0.

- Preset options live in five places: `availableActions()` and the option clamp in `Engine.narrate`;
  the narrator prompt ("Give up to 3 options"); `parseNarration`, which throws when `options` is
  missing; `style` in `data/world.json` ("three options at the end of every turn"); and the keys 1-3
  in the client and `README.md`.
- `parseFreeAction` knows about ten English verbs. Any other text is recorded as `say` and only
  narrated, so "I punch Marta" changes nothing and Spanish input never maps to an action.
- `memoryFromEvent` has no case for `say` or `enter`, so they become "Niko did something."
- `recall` is called only for Niko, and no caller ever passes `keywords`.
- One model (`cfg.model`) serves narrator and architect. Reasoning is a single global flag.
- `post()` uses `AbortSignal.timeout(30_000)`, a total timeout that also aborts a streamed body, so
  any reasoning model would be cut mid-turn.
- `logUsage` writes the role `'narrator'` for every call, including the architect.
- Any narrator failure or a spent budget silently falls back to template text, which lowers quality
  without telling the player.
- *Verify:* whether the client sends arrow keys through `/api/turn` as `move` actions or locally.
- *Verify:* that `record()` can stay synchronous while memory text is written later ([Sec. 4.8]).

## 3. Decisions

Settled:

- **No preset options.** The player's only input is free text in any language.
- **Quality over latency.** Slow, multi-call turns are acceptable.
- **The LLM proposes, the engine decides.** Effects are typed, validated and committed by the engine
  through the same `Action` API as everyone else.
- **Offline mode keeps working.** Without an API key the deterministic parser becomes the
  `OfflineInterpreter`, so tests and zero-cost play still run.

*Needs approval* (defaults in brackets):

1. **Risky outcomes** [the engine rolls with `rngFor(seed, tick, "risk")` and the LLM only
   interprets the result]. Keeps replays deterministic. The alternative is the LLM deciding freely.
2. **One effect = one tick** [yes], so NPCs react while Niko walks several tiles. At most
   `maxEffects` (default 4) per turn.
3. **Failure policy** [retry twice with backoff; if the interpreter still fails, the turn is
   rejected with no state change and the text stays in the box; if the narrator fails after the
   effects committed, that single turn uses the offline narration and is flagged `degraded`].
4. **Spend cap reached** [roles switch to offline and the turns are flagged `degraded`], as today.
5. **Arrow keys and WASD** [stay as direct `move` actions that skip the interpreter]. They are an
   explicit command, not interpreted text.
6. **Reasoning defaults** [on for interpreter, architect and continuity; off for narrator and memory].

## 4. Scope

### 4.1 Effects and the Interpreter interface

```ts
export type Effect =
  | { kind: "move"; path: Dir[] }                       // up to rules.maxPathSteps
  | { kind: "wait" }
  | { kind: "speak"; to: string | null; text: string; tone?: "ask" | "reassure" | "press" }
  | { kind: "end_conversation" }
  | { kind: "interact"; target: string; verb: string }  // examine, open, take... object ids only
  | { kind: "ability"; id: string; target?: string };

export interface Interpretation {
  effects: Effect[];                // at most rules.maxEffects
  impossible?: { reason: string };  // nothing valid could be extracted
  keywords: string[];               // names and objects the text mentions, for recall
}
export interface Interpreter {
  interpret(c: InterpretContext, onDelta?: DeltaSink): Promise<Interpretation>;
}
```

Attacks and any other kind the engine cannot resolve yet come back as `impossible` with a reason, so
the narrator can say why. `OfflineInterpreter` wraps the current `parseFreeAction` and returns the
same results it returns today.

### 4.2 Interpreter call

Input: the player's text, Niko's sheet, Ether, `rules.json`, the zone with object and portal ids,
visible characters with ids and proximity words, open conversation, Niko's recalled memories, the
rolling summary and the last narrations. The system prompt requires:

- use only ids present in the situation, never invent characters, objects or abilities;
- understand any input language and keep `speak.text` in the player's own words;
- return JSON only, no narration, no options;
- return `impossible` with a short reason instead of guessing.

The call is logged with role `interpreter`. Its JSON is parsed like `parseNarration`: tolerant of
fences, strict about shape.

### 4.3 Rules file

`data/rules.json`: abilities (`id`, `ether_cost`, `range`, `description`), `maxEffects`,
`maxPathSteps`, hard limits written as short sentences ("Niko cannot fly") and the risk policy.
It is validated on load like `loadOpening` and injected verbatim into the interpreter prompt. The
opening's `brace` moves here and `data/opening.json` references it by id.

### 4.4 Engine

Split `runTurn`'s switch into `apply(action)`. Each effect becomes one existing `Action`
(`move` by step, `talk`/`reply`/`leave`, `examine`, `wait`) or a new `ability` action, so there is
still a single action API. The flow for a free-text turn:

1. interpret; 2. for each effect in order, validate and apply, advancing one tick; the first
rejected effect stops the chain; 3. collect `resolved` and `rejected` (with reasons) for the
narrator; 4. narrate; 5. quality passes ([Sec. 4.7], [Sec. 4.8]).

A risky `ability` rolls through `rngFor` and the result goes into the event data.

### 4.5 Remove preset options

- Engine: delete `availableActions()` as a menu and the option clamp; keep the checks it did as the
  validators `apply` needs.
- Narrator: `Narration = { text, degraded? }`; `parseNarration` stops requiring `options`; the system
  prompt drops the options rule and keeps "end on pressure, a question or a visible choice".
- `OfflineNarrator` returns text only.
- Data: remove the options sentence from `data/world.json` `style`.
- `state()` stops sending `options`; old `narration` events that contain them still load.

### 4.6 Roles, models, timeouts

`LlmRole = "interpreter" | "narrator" | "architect" | "continuity" | "memory"`. Environment:
`<ROLE>_MODEL` (defaults to `NARRATOR_MODEL`) and `<ROLE>_REASONING` replace the global
`NARRATOR_REASONING`. `post()` takes an **idle** timeout (`<ROLE>_IDLE_MS`, default 120 000 for
reasoning roles, 60 000 otherwise) that resets on every chunk, instead of a total 30 s. `logUsage`
receives the role. `SPEND_CAP_USD` stays global; the Debug tab adds cost per role.

### 4.7 Continuity check

After the narrator, the existing deterministic checks run first (repeats, tile counts). Then the
`continuity` role receives the narration, world facts, known facts, recent narrations, resolved and
rejected effects and returns `{ ok, problems[] }`. When not ok, the narrator rewrites once with the
problems appended. The rewrite is accepted either way, and the problems are kept in the logged
response. At most two extra calls per turn.

### 4.8 Memories and the rolling summary

- Event types where the wording matters (`say`, `talk`, `talked`, `arrives`, `enter`, interactions)
  skip the template inside `record()`. At the end of the turn the `memory` role writes one sentence
  per witness, limited to what that witness could perceive, plus an importance from 1 to 10.
  Memory rows are inserted after their event, never edited, and a failed call inserts the template
  text, so every witness always gets a memory and memory stays append-only.
- Low-importance types (`move`, `wait`, `appears`) keep the template: no call.
- `MemoryQuery.keywords` now comes from `Interpretation.keywords`.
- Migration 5 adds `story_summary (id, upto_tick, text)`. Every `rules.summaryEveryTicks` the
  `memory` role writes a new row from the previous summary plus the events since. The newest row is
  sent to interpreter and narrator as `story_so_far`.

### 4.9 Client

Remove the options panel and the 1-3 keys. The free-text box is the only input; arrows and WASD
stay ([Sec. 3]). The status line shows the stage (`interpreting`, `resolving`, `narrating`,
`checking`) from a new SSE `stage` delta, and keeps showing streamed reasoning when the model emits
it. A `degraded` narration is marked. The client still only draws snapshots and sends commands.

## 5. What must not break

- The engine is the only writer of state; effects never write anything themselves.
- One `Action` API: no actor gets a shortcut, and the interpreter cannot produce an action the
  engine does not already validate.
- The client never simulates.
- Determinism: randomness only through `rngFor`; the resolved effects and every LLM response are
  stored, so a turn can be audited without calling a model again.
- Migrations are append-only; a v0.4.0 save loads, including the `fall` phase and old narrations.
- Every LLM call is logged with its real role, tokens and cost.
- Narration still never states distances as numbers and never invents facts.

## 7. Out of scope

- NPC dialogue generated from persona and history, and NPCs using their own memories (next DEV).
- Inhabitants for generated buildings and off-screen simulation of other zones.
- Combat, health, inventory and embeddings.
- Adult ops (still pending; when added they keep the adults-only and consent preconditions in code).

## TL;DR

Replace preset options with an LLM interpreter that proposes typed effects from free text under
`data/rules.json`; the engine validates and commits them through the single `Action` API. Each role
gets its own model, reasoning flag and idle timeout, and quality passes (continuity check,
LLM-written memories, rolling summary) run before a turn closes.
