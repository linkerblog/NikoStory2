# Dev-004: Opening — Niko falls from the sky

[Feature] [Engine] [World] [Narrator] [Client] [Data]

The current start drops the player into a bedroom with "Niko wakes up in a bedroom he does not
know", which has no hook, no stakes and no link to who Niko is. The original story starts with
Niko, a bioengineered combat unit from another dimension, falling out of the sky into our world.
This DEV replaces the wake-up start with a short scripted fall (three beats, three choices each),
a deterministic landing inside the existing house zone, and a world/character data pack taken from
the original story so the narrator writes from the real setting. The fall uses the same `Action`
API, the engine stays the only writer of state, and a savegame from v0.2.0 keeps playing as before.

## 2. Findings / current state

Observations come from reading the v0.2.0 source and from a simulated offline playthrough.

- `Engine.start()` narrates a fixed line ("Niko wakes up in a bedroom he does not know") and
  nothing in the data explains why Niko is here. `data/scene.json` asks "Why is Niko in this
  house?" but the house has no answer beyond two NPC facts.
- Niko starts with Ether 3 of 100 (`data/niko.json`, flagged provisional in `README.md`), so the
  Ether bar is never meaningful and no action spends it.
- The narrator receives `niko_sheet`, `place`, `scene` and memories, but no description of the
  world (year, country, hybrids, mana, the gender ratio), so it cannot write the original setting.
- The only way to act in the first turns is `wait` until an NPC arrives. In the simulated run the
  first decision appeared at tick 13.
- Perception, witnesses and memory are line-of-sight based and already support a dramatic arrival
  event: anyone who can see the landing tile witnesses it and remembers it.
- *Verify:* that `Engine.start()` can branch on a stored phase without touching the `started`
  flag used by existing saves.
- *Verify:* that `state()` and the client can show a non-map view without the client holding state.

Source note: the lore in [Sec. 4.1] comes from the brainstorming summary of the original KoboldAI
session plus the fields already in `data/niko.json`. The session file itself was not available
when this plan was written, so every lore line is marked *confirm* in the data comments below.

## 3. Decisions

Settled:

- **The fall is a phase, not a zone.** Engine is still one zone; the fall happens "above" it and
  ends inside it. Zone generation through `D` stays out of scope.
- **Fall turns do not advance the world.** No tick, no NPC steps, no witnesses, no memories until
  the landing. The landing is the first real tick, so the same seed and choices replay the same
  game.
- **Altitude is a label, never a number.** Same rule as distances (`docs/done/Dev-003.md`).
- **Legacy saves skip the opening.** A database without `phase` behaves as `phase = "play"`.

*Needs approval* (defaults in brackets):

1. Number of fall beats [3].
2. Fall choices [`steer`, `brace`, `let_go`] and what each does ([Sec. 4.2]).
3. `brace` costs [2] Ether and Niko starts with [3] Ether, so bracing is affordable once.
4. Landing rule: `steer` lands in the living room near Marta, the other choices land on a seeded
   free tile anywhere in the house.
5. Impact has narrative and Ether consequences only (no health system yet): a hard landing zeroes
   Ether; a soft one keeps what is left.
6. Scene question becomes "Why did Niko fall into this world?" with two placeholder facts that
   the original story should replace.

## 4. Scope

### 4.1 Data

No migration: `phase` and `fall_beat` live in the existing `settings` table.

`data/world.json` (every line *confirm* against the original session):

```json
{
  "year": 2030,
  "country": "United States",
  "facts": [
    "Hybrids (humans with animal traits) are common and accepted.",
    "Every living thing carries mana.",
    "Women outnumber men about ten to one; gender roles are inverted compared to ours."
  ],
  "style": "Short sentences, fast rhythm, no decorative text, three options at the end of every turn."
}
```

`data/niko.json` gains `origin` and `core` inside `data` (existing keys stay):

```json
"origin": "bioengineered combat unit from another dimension",
"core": "Ether Core"
```

`data/opening.json`:

```json
{
  "beats": [
    { "altitude": "high above the clouds" },
    { "altitude": "through the clouds" },
    { "altitude": "above the rooftops" }
  ],
  "abilities": { "brace": { "ether_cost": 2 } },
  "landing": { "steer_room": "living_room" }
}
```

`loadOpening` validates it on load, like `loadZone`: at least one beat, a known room id, a
non-negative integer cost. A malformed file is rejected, not trusted.

### 4.2 Engine: phase and the `fall` action

Add to the `Action` union (`src/engine.ts`):

```ts
| { type: "fall"; choice: "steer" | "brace" | "let_go" }
```

- `phase` is read from `settings`: `"fall"` on a new game, `"play"` afterwards or when missing.
- While `phase = "fall"`, `availableActions` returns only the three `fall:<choice>` actions (the
  `brace` action is omitted when Ether is below its cost) and `takeTurn` rejects everything else
  with "You are still falling."
- Each `fall` action stores its choice in `settings.fall_log` (JSON list) and increments
  `fall_beat`. A `brace` is validated in the engine against Ether and spends it there, so a client
  or the LLM cannot skip the cost.
- When `fall_beat` reaches the number of beats, the same call resolves the landing ([Sec. 4.3])
  and continues into the normal world step for that turn.

### 4.3 Deterministic landing and the `arrives` event

- Candidate tiles: floor tiles that pass `free()`. With `steer` the candidates are the tiles of
  `landing.steer_room`; otherwise all free tiles. The pick uses `rngFor(seed, 0, "landing")`.
- Impact is `soft` when `brace` was chosen at least once and Ether allowed it, otherwise `hard`.
  `hard` sets Ether to 0; `soft` keeps the remainder.
- The engine moves Niko to the tile and records `arrives` with `withWitnesses = true`, data
  `{ impact, choices }`. Existing `record()` writes witnesses and one memory per witness.
- `phase` becomes `"play"`, `visible` is initialized from the landing position, and the world
  advances one tick with the existing code path (agendas start moving because the NPCs now
  witnessed the arrival).

### 4.4 Narrator

- `Context` gains `world` and `arrival` (`{ phase, altitude, beat, beats, impact?, choices? }`).
  `payload()` sends `world` as `world` and the arrival block as `arrival`; the system prompt
  adds: "The world facts are true; do not contradict them; do not invent new ones."
- Offline narrator gets templates per beat and per impact so the opening works with no network:
  three beat lines keyed by `altitude`, and one `soft`/`hard` landing line. Altitude words pass
  `narrationRejected` because they contain no numbers.
- The engine's option filter is unchanged: only `fall:*` ids survive during the fall.
- `Engine.start()` for a new game narrates the first fall beat instead of the bedroom line; it
  keeps using the same `started` flag so a restart does not repeat it.

### 4.5 Client

`state()` adds `phase` and, during the fall, `fall: { altitude, beat, beats }`. `public/index.html`
draws a plain sky panel with the altitude label instead of the map while `phase = "fall"`, then
the map as today. The client still holds no game state; keys 1-3 already select options.

### 4.6 Memory and scene

- `data/memory_rules.json`: add `"arrives": 9` to `importance` so the landing outranks movement
  noise in recall.
- `data/scene.json`: new question and two facts revealed by the existing agendas. The facts are
  placeholders until the original story supplies the real ones:
  `fact_marta_warning`: "Marta saw a light fall from the sky and came to warn Niko that people
  will come looking for it." `fact_ivy_letter` keeps its id with text to be replaced.

## 5. What must not break

- **The engine is the only writer of state.** The fall, the Ether spend and the landing are
  decided in `Engine.takeTurn`; the narrator only proposes text and options.
- **One action API.** `fall` is an `Action`; the client sends it to `POST /api/turn`.
- **The client never simulates.** It draws `state()` and sends commands.
- **Determinism.** The landing uses `rngFor`; no `Math.random`, no wall-clock time.
- **Migrations stay append-only.** None is added; `phase` lives in `settings`.
- **Legacy saves.** A v0.2.0 `game.db` keeps `started = 1` and no `phase`, and plays unchanged.
- **Every LLM call is logged** to `llm_calls`; the fall beats reuse the same narrator path.

## TL;DR

Replace the bedroom wake-up with a three-beat fall from the sky: a new `fall` action and a `phase`
stored in `settings` (no migration), one Ether-costing `brace`, a deterministic landing in the
house that emits a high-importance `arrives` event seen only by its witnesses, and `world`/`origin`
data from the original story fed to the narrator, with offline lines and a sky view in the client.
Old saves keep playing unchanged. Verified by `test/opening.test.ts`, `npm run check` and two
manual playthroughs; released as `v0.3.0`.
